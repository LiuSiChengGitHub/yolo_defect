A / 已有演示目录

打开 HTML，再启动工作台

  1. 完整解压或复制 yolo-defect-qt/，放在可写目录。
  2. 打开 demo/index.html，即本指南。
  3. 双击目录根部 run.cmd。默认载入 FP32 配置及一个样例。
  4. 点击“运行检测”，对比原图、检测框及明细。

成品带上 Qt、OpenCV、ORT 运行依赖和样例；运行无需安装 Qt 开发套件、编译器或 Python。

B / 从源码构建

复用正式开发入口

安装 MSVC x64、Qt 6 Widgets MSVC 套件、OpenCV 和 ORT C++ SDK，填写机器本地配置。依赖版本与详细路径见客户端工程说明。

在仓库根目录首次配置；已有配置勿覆盖
Copy-Item cpp_infer/tools/stage1.local.example.psd1 cpp_infer/.stage1.local.psd1
Copy-Item cpp_infer/tools/qt.local.example.psd1 cpp_infer/.qt.local.psd1
# 编辑两份本地配置中的 SDK 路径
.\cpp_infer\tools\qt.cmd build
.\cpp_infer\tools\qt.cmd run
.\cpp_infer\tools\qt.cmd package

打包到被 Git 忽略的 dist/yolo-defect-qt/。当前没有通过本页面提供预编译下载；可自行打包或使用作者交付的完整目录。

本网页是操作指南与媒体展示，不在浏览器里运行推理。默认 FP32 模型 models/best.onnx 和 data/images/val/ 样例已随源码跟踪；INT8 为可选生成产物。成品包是否包含 INT8，以目录内 models/ 和打包清单为准。

演示时按这个顺序

  1. 单图：运行默认样例，展示生效参数、类别与置信度。
  2. 目录：输入方式选“图片目录”，选择 samples/，开始批处理。运行期间只有忙碌状态，完成后显示真实最终计数。
  3. 逐图查看：点选结果行；在图像上滚轮缩放、拖动平移，点击检测框联动明细。双击或“适应”恢复全图。
  4. Manifest：选择样例 manifest，说明其顺序来自清单。目录模式按 Runtime 的相对路径规则排序。
  5. 停止：对较大的目录运行并点击“停止”。当前在途图片完成后收尾，可再次开始。小样例可能在点击前已经结束。
  6. 结果：通过底部按钮打开逐图 JSON、批次汇总或结果目录。

不依赖 Qt 的工程核心

Qt 后台线程调用既有 Runtime。批处理仍由有界队列、worker 独占的 pipeline/session 完成；GUI 直接发出线程安全的协作停止请求。结果浏览读取已保存的 JSON / PNG，快速切换时旧预览不会覆盖新选择。

01 / CONTRACT

配置与模型契约

FP32 / INT8 通过配置切换。界面展示实际生效的模型、阈值、类别及输入尺寸。

02 / CONCURRENCY

响应与生命周期

模型加载、推理、写出在后台；GUI 线程只操作控件。关闭运行中的窗口先等待收尾。

03 / PRESENTATION

可维护的展示层

布局与 QSS、表格 Model、图像绘制集中在 Qt 模块。调整色彩或图标不改变结果协议与推理调度。

验收看什么

验证范围检查内容复现入口
真实检测一致性FP32 / U8S8 单图、目录 / manifest，比较 GUI 与 CLI 的结果和顺序。qt.cmd test -Screenshots
交互与任务收尾界面响应、损坏图片、停止后重启、运行中关闭、选择联动、缩放。Qt 集成测试与原生平台截图检查
成品运行依赖限制 PATH，检查包内 Qt 启动与 Runtime 真实检测。包根目录：powershell -NoProfile -ExecutionPolicy Bypass -File .\verify.ps1
原有主链关闭 Qt 独立构建并执行 Runtime / CLI 回归。YOLO_DEFECT_BUILD_QT=OFF

界面中的任务总耗时包含加载与文件写出；性能结论使用原有独立 benchmark / profiling 工具。Qt 桌面交付当前验证 Windows x64，原 Runtime 的 Linux / AArch64 验证与桌面支持范围分别记录。

运行依赖、模型与故障定位

源码开发需要匹配 x64 的 Qt / MSVC / OpenCV / ORT SDK；成品目录由 windeployqt 收集 Qt 依赖，再加入 Runtime 依赖。请整体移动演示目录，不要只复制 EXE。

配置里的模型声明路径相对配置文件解析；声明里的模型路径相对声明解析。换模型时同步检查输入形状、类别、输出语义；只更换模型文件名不一定满足契约。INT8 生成与环境要求见仓库的 C++ 技术手册。文件缺失、输入损坏或配置不匹配时，先查看界面的错误与生成的 JSON。

包内保留项目和随附依赖许可材料。公开分发前按实际使用的 Qt、模型、数据及第三方组件许可核对发布方式。
