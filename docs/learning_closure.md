# 教学闭环与口述格式

本文只在一个 S2 实现单元收口、用户进行 L1/L2 验收，或明确要求复盘/面试准备时读取。日常实现、构建和调试不预读本文。

## 九部分收口

除非用户明确要求简短状态答复，每个实现单元的最终回复依次包含：

### 第一部分的强制双层结构

第一部分不能只输出五分钟口述，必须在回复最开头按以下顺序连续给出两层内容：

1. **五分钟口述：**先给出一段可直接练习和用于面试的自然口述。它必须能独立讲清目标、问题、动机、主要工作、关键选择、验证、结果和限制，长度以正常语速约五分钟为目标。
2. **教学级完整讲解：**紧跟口述，对同一单元做不限于五分钟的系统教学。它不能只是扩写文件清单或重复口述，必须让读者在不预先熟悉实现、不跳转其他文档的情况下，理解单元的完整来龙去脉。

教学级完整讲解至少覆盖：

- 本单元处于整体路线的什么位置，前置状态、目标、要解决的问题、输入输出和明确非目标是什么；
- 端到端链路按什么顺序运行，每一步具体做什么，前后数据或控制关系如何连接；
- 涉及哪些关键技术、概念、协议、算法或工具，并解释其工作机制、相互关系和在本单元中的作用，不能只罗列术语；
- 为什么需要每一步，为什么采用当前设计，主要备选方案、trade-off，以及省略或替换后会产生什么影响；
- 具体实现中的核心数据流、控制流、契约、算法、ownership 和错误语义；不相关的细枝末节可以留到后续部分；
- 如何验证 Runtime、产品行为、任务质量、性能或其他目标，为什么选择这些验证，预期和实测分别是什么，失败或负向结果应如何解释；
- 最终结果、完成判定、未完成项、证据边界、局限和下一步，明确区分“实现完成”“练习收口”“严格验收通过”等不同口径；
- 用清晰的因果链把“问题 → 选择 → 实现 → 验证 → 证据 → 结论”连接起来，使整个单元完整、自洽并能承受连续追问。

五分钟限制只适用于开头口述，不限制后面的教学级讲解。后续第 2–9 部分负责按模块、文件、人工流程、代码、运行和面试等维度进一步索引和展开，但不能替代第一部分的教学闭环。本双层结构适用于九部分单元收口或完整复盘；用户单独要求“给出口述答案”时，仍按本文末尾的纯文本格式执行。

九部分依次为：

1. **讲解本步工作：**严格按上述“开头五分钟口述 + 紧随其后的教学级完整讲解”输出。
2. 新增或修改了哪些模块，为什么这样设计；说明关键 trade-off、输入输出和异常语义。
3. 哪些文件变化、目录树如何变化，各文件在链路中承担什么职责。
4. 不使用 Codex 时，准确的人工实现流程是什么。
5. 入口函数、核心类/函数、输入输出、ownership 和宏观伪代码。
6. 如何运行、测试、调试、调参、修改和定制；给出实际命令、证据路径与常见失败诊断。
7. 哪些验收问题和连续追问能证明达到面试理解深度。
8. 哪些代码最可能被追问并应进入代码练习；给出文件和当前行号。
9. AGENTS.md、README.md、README_zh.md 是否同步了状态、命令、证据、限制、路径和关键接口。

## 口述答案格式

当用户说“给出口述答案”时，只输出可复制纯文本，使用“题号.回答”，答案间空一行；不复述问题，不加标题、项目符号、代码块、前言或总结，除非用户明确要求。
