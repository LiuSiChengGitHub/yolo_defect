```
软件工程的起点不是“写代码”，而是把一个模糊的问题逐渐变成一个可实现、可验证的系统。需求分析解决“为什么做、做什么”，包括功能需求和性能、可靠性、安全性等非功能需求；SPEC 把需求进一步精确化，规定输入、输出、状态、异常、边界条件、验收标准等，让开发和测试对“正确行为”形成一致理解；架构设计则决定系统如何拆分、模块之间如何协作、数据由谁拥有、出现故障时怎么办，以及哪些技术决策需要长期保持稳定。

一些值得记住的软件工程关键词是：Requirement、SPEC、Functional Requirement、Non-functional Requirement、Acceptance Criteria、Invariant、State Machine、API Contract、Architecture、Module Boundary、Data Ownership、Design Doc、RFC、ADR、Trade-off、Failure Model、Idempotency、Consistency、Backward Compatibility、Observability、Testing、Traceability。它们背后的共同思想其实只有一个：管理复杂度和不确定性。

一个比较成熟的思考顺序是：先弄清 Problem 和 Requirements，再确定 Invariants 和 SPEC，然后考虑 Scale、Latency、Availability、Consistency、Failure、Security 等约束，最后才选择数据库、消息队列、语言、框架、微服务等技术。也就是“从问题推导技术”，而不是“学了一个技术以后找地方使用”。
```
