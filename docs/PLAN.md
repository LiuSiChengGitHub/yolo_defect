## 背景与目标

面向 2026 秋招，主线仍是非互联网外企的 C++ 软件开发与边缘 AI 工程化，借助 Qt 扩展工业、医疗设备、仪器及工程软件的桌面客户端岗位。已有 C++17、RAII、多线程、Linux、CMake、GTest 和性能分析基础；本次优先迁移这些能力，用较少的新概念建立可演示、可解释的 Qt Widgets 项目经历。

仓库已完成 `RuntimeConfig + ModelArtifactSpec → DetectorPipeline → BatchRunner` 主链，具有 FP32/INT8、单图与目录/manifest 批处理、结果写出、benchmark/profiling 及跨平台验证。新增一个漂亮、真实可用的“工业缺陷检测工作台”，让面试官从 GitHub 首页的截图、短演示和运行说明快速理解项目；已有简历中的架构、算法、量化、并发和跨平台成果继续成立。

## 技术取舍与边界

- **采用 C++17 + Qt 6 Widgets + 现有 CMake。** 首期交付 Windows x64，匹配现有 MSVC/OpenCV/ORT 工具链。优先标准控件、布局和少量 QSS，实现统一配色、留白、字体层级与清晰的图像展示。Linux GUI 验证可后续补充。

- **保持三层解耦：** `应用层（CLI / Qt 客户端）→ yolo_defect::runtime → yolo_defect::project_core`。Qt 与 CLI 是并列入口，直接复用 Runtime 公共接口；推理、后处理、批处理调度和结果格式继续由原模块负责。Qt 类型、事件循环和界面逻辑只留在客户端，不通过启动 CLI 或 Python 服务绕接业务。

- **保持纯增量。** GUI 使用独立 target 和默认关闭的构建选项；未安装 Qt 时，原构建、测试、CLI、core-only 和 AArch64/QEMU 链路照常使用。确需补充公共能力时，只做兼容旧调用方式、无 Qt 依赖的小扩展，不重构既有主链。

- **保持配置驱动。** 复用现有配置加载与校验，FP32/INT8 切换对应 RuntimeConfig；模型路径、类别、阈值和路径解析规则沿用现有契约。首版选择配置并展示生效参数即可，不必新增配置编辑器。最近目录、窗口状态等界面偏好可用 QSettings 保存。

- **控制学习面。** 本轮不引入 QML/JavaScript、第二套构建体系、网络/数据库、相机/PLC 接入或复杂插件架构；也不要求把 benchmark、profiling、训练与量化流程全部搬入 GUI。保留既有性能证据与计时口径，不用 GUI 耗时替代简历中的 benchmark 数据。

- **新增文件与目录要符合工程标准，使得仓库结构清晰不凌乱。**

## 三步实施

### 1. 打通单图客户端闭环

完成可选 Qt 构建与一个有完整视觉结构的主窗口：选择配置和图片、执行检测、查看原图/检测框及类别置信度、查看或打开结果输出。复用 `load_runtime_contract`、`DetectorPipeline` 和现有 writer；当前单图接口要求至少一种文件输出，首版按现有输出机制接入。

从第一步就将配置/模型加载、推理和写出放到后台，界面提供明确的运行、完成与错误反馈。界面至少能查看当前模型和生效参数，切换配置后重新运行，避免展示与实际推理条件不一致。

**验收：** 使用已有 FP32 和正式 U8S8 INT8 配置均能完成真实检测；同一配置、同一输入的检测结果与 CLI 一致；运行时窗口仍能响应，错误可见且能继续使用。

### 2. 接入批处理，完成展示与交互

接入现有目录/manifest 输入和 `BatchRunner`，提供开始、协作停止、运行状态、完成汇总及逐图结果浏览；支持从结果表格选择图片查看检测结果和失败原因。继续使用现有 worker/session 与有界队列，Qt 后台线程只负责调用和界面适配，不另建推理调度系统。

当前批处理接口同步返回最终汇总，没有实时逐项进度通知；首版使用忙碌状态与最终计数，不模拟百分比。停止复用线程安全的 `request_stop()`，允许正在执行的图片完成，停止由 GUI 线程直接调用该 Runner 的 `request_stop()`，不通过排队信号发给正在执行 `run()` 的后台对象（其事件循环被同步调用占用，排队的取消要等整批结束才会执行）；每次批任务新建 runner，处理好重复启动、停止和关闭窗口时的生命周期。真实逐项进度仅作为可选的小扩展，不作为首版完成条件。

统一打磨配置/输入区、图像查看区、结果表格与状态区的布局，完善缩放查看、结果选择联动、空状态与失败状态。以标准控件和轻量绘制完成工业软件风格，视觉效果应服务于真实检测流程。

**验收：** 批处理期间界面可用；损坏图片不影响其他任务，结果顺序和汇总与 Runtime 一致；取消后能够再次启动，运行中关闭窗口能正确收尾；表格与图像展示对应准确。

### 3. 验收、可视化交付与工程学习补充

复用既有测试和比较工具，完成 Qt/CLI 同配置结果一致性、批处理生命周期及交互验证；在独立目录关闭 Qt 构建并执行原 Runtime/CLI 回归。共享 Runtime 与跨平台实现没有变化时，不重复无关性能实验或平台检查。

交付可移动的 Windows 演示目录，包含运行依赖、相对路径配置、模型及少量样例、启动脚本和验证脚本。将目录地图、启动方式、使用流程、故障定位集中到 `docs/demo/index.html`，支持离线打开；完整 SDK、模型获取与配置说明链接到技术 README。页面明确区分截图展示与实际本地推理。
