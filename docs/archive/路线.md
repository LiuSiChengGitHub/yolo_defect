### 6.12 每周推进节奏

不要纯串行，也不要每天平均切换。

采用：

```text
阶段主项目 + 副项目保温
```

原因：

```text
项目1的 C++ / CMake / ORT / TensorRT 需要连续上下文。
项目2的数据库 / API / Agent workflow 也需要连续上下文。
每天完全交替会导致两个项目都浅推进。
但完全一个月只做一个项目，又会让另一个项目启动太晚。
```

推荐节奏：

```text
每周 3 个项目推进单元：

单元 A：主项目深推进
单元 B：主项目继续推进或验收
单元 C：副项目保温推进
```

例如：

```text
6 月上旬：
A/B 给项目1，C 给项目2。

7 月中下旬：
A/B 给项目2，C 给项目1。

8 月：
A 给项目1，B 给项目2，C 做双项目验收与文档。
```

每周至少产出：

```text
主项目：
一个可运行模块或一个关键闭环。

副项目：
一个小模块、一个 README 更新、一个测试或一个设计冻结。
```

每周不允许：

```text
两个项目都只改 README。
两个项目都没有可运行变化。
为了切换项目而切换项目。
没有验收就进入下一个 Codex 任务。
```

核心原则：

```text
项目可以由 Codex 快速写代码。
但每个模块为什么存在、怎么实现、怎么测试、怎么被追问，必须由你吃透。
```
